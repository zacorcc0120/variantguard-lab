# Languages

The page is available in English (`en`) and Simplified Chinese (`zh-CN`).

## How the language is chosen

1. A saved choice in `localStorage`, key `variantguard.locale:v1`, wins.
2. Otherwise the browser language list is used. A `zh` language selects `zh-CN`.
3. Otherwise the page stays in English.

The switcher in the header writes that key and keeps the loaded files, assumptions and findings. Only the language preference is stored. Product CSV text is not written to `localStorage` or `sessionStorage`.

Refreshing the page reads the saved choice again. The files themselves are gone after a refresh, because they are held in memory only.

## What changes with the language

Translated: interface labels, rule titles, finding prose, assumption text, scenario blurbs.

Not translated, and not changed by the language:

- finding ids
- rule ids such as `VG-VAR-001`
- severity
- the number of findings
- Shopify column headers inside the data
- the CSV report header row

A missing translation key stays visible as the key, or falls back to the English finding sentence. It is not replaced with an empty string.

## Exports

CSV column headers stay English. The prose columns follow the language on screen. A Chinese CSV is prefixed with a UTF-8 BOM so Excel on Windows does not read it as the system code page. English CSV has no BOM.

JSON keeps the existing English fields and adds a `localized` object for the active language.

## Parse errors

Encoding, ragged rows, a missing Handle column and the other parser findings use the `parse.*` dictionary entries. Switching language does not change their ids or severities.
